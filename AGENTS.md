# AGENTS.md — MILPOS Project Conventions

## What this project is
Multi-tenant POS + inventory system: .NET 10 CQRS/MediatR backend (`SourceCode/SQLAPI`), Angular 20 SPA (`SourceCode/Angular`), Electron desktop shell, SQLite (desktop) / PostgreSQL (cloud).

## Authoritative documentation
- **Workflow specs:** `New-Documents/01–10` (code-verified, `WF-x.y` IDs), gap catalog `New-Documents/11`
- **Test specification:** `Test-Documentation/` — 680 test cases (TC-Dxx.nnn), strategy in `00_TEST_STRATEGY.md`, Postman plan, Playwright journeys. Every automated test must trace to a TC ID.
- Gap-Target tests are RED by definition (drive enhancements); Gap-Char tests pin current behavior. Never weaken assertions to make tests pass.

## Test infrastructure facts (hard-won)
- `TestWebApplicationFactory` uses **`UseSetting`**, NOT `ConfigureAppConfiguration` — minimal-hosting apps apply factory config callbacks *before* appsettings.*.json, so file settings would override them.
- Hangfire SQLite storage needs a **bare file path** (not `Data Source=…`).
- `AuthenticationController.Login` NREs without a `CF-Connecting-IP` header in test servers — all test clients add it.
- SQLite migrations are **3 migrations behind** the EF model (`TestSeed.PatchMissingColumnsAsync` shims the 4 missing columns on the test DB only — each entry is a product finding to fix properly).
- `RoleClaim.ActionId` has FK to Actions → seed claims directly, never via `AddClaimAsync`.
- Audit interceptor stamps `CreatedBy/ModifiedBy` from `DefaultUser:DefaultUserId` — that user must exist or audited writes FK-fail.
- Seeding order: tenants → identity (roles/users) → Page/Action/RoleClaims → business rows (audit FKs require existing users).
- **Claim names are exact strings** — `PO_ADD_PO`, `SO_ADD_SO_PAYMENT`, `PO_DELETE_PO`, `INVE_*` etc. Never guess (`PAY_*` names don't exist); check the controller's `[ClaimCheck(...)]` first.
- **EF replaces Guid.Empty PKs** on insert (client-side value generation) — code-level ACC-05 (Transaction Id = Guid.Empty) is not observable in the DB; don't assert empty transaction ids.
- xUnit collections are **serialized** (`xunit.runner.json`) — parallel factories × Hangfire (WorkerCount = CPU×5 each) caused 2-minute HTTP timeouts under the coverage collector.
- `TestWebApplicationFactory.UsingDbAsync` has void (assert) and `<T>` (query) overloads; stock-sensitive tests must capture a "before" value (same-class tests share the fixture DB).
- Unit tests for strategies: real `AccountingEntryFactory` + mocked repos; `IGenericRepository.Add` is void → Moq `.Callback` only.
- **Background hosted services are removed in the test factory** (Hangfire server, POS.API.BackgroundServices, ApiAndQueriesProfiler drain writer) — the profiler wrote every request's query logs back into the main SQLite file, causing lock storms (14 min → 2.7 min suite time after removal). Factory `ConfigureServices` callbacks DO run after the app's registrations in minimal hosting (verified empirically).
- `SalesDeliveryStatus.DELIVERED = 0` — the enum default; non-POS orders must set `PENDING` explicitly or the update guard 409s.
- **API JSON binding is Newtonsoft** — a `null` sent for a non-nullable enum field (e.g. `deliveryStatus`) yields 400 "Error converting value {null}". In anonymous `PostAsJsonAsync` payloads, **omit** enum properties whose value is null instead of setting them to null.
- **`ApiKeyAuthenticationMiddleware` "last used" stamp is a silent no-op**: it fetches the tenant without `.AsTracking()` on a NoTracking context — `ApiKeyLastUsedDate` never advances (SEC-07 write-cost assumption is dead code; Gap-Char in `ApiKeyCharacterizationTests`).
- **Tenant registration needs a live master tenant**: `SeedTenantDataAsync` clones the configured `MasterTenant`; without one it falls back to CSV seeding that 400s on the `Actions.PageId` FK (Actions.csv inserted before Pages.csv; SQLite enforces immediately). The test factory sets `MasterTenant:TenantId` → seeded Tenant A so the production clone path runs. `Tenants.Name` is NOT NULL — always send `name` in register payloads.
- **PO return with refund always 500s** (double-save: PaymentService flushes the UoW, the handler's follow-up `SaveAsync()` affects 0 rows → treated as failure → rollback). SO return does not have this second save. **FIXED in Wave 1** (redundant save removed); Gap-Char flipped to Gap-Target and GREEN (`Should_PostRefundAndPersistReturn_When_PurchaseReturnRequestsRefund`).
- `POSDbContext` defaults to **NoTracking** — test seeds that mutate fetched entities must use `.AsTracking()` or the change silently does nothing.
- Stock transfer handler **overwrites `ReferenceNo`** with a generated number (`GenerateStockTransferNumber`) — read the reference back from the response instead of asserting on the request value.
- SEC-04 is worse than documented: `ResetPasswordCommandHandler` guard `entity == null && entity.ResetPasswordCode != request.Token` means the token is **never validated** (any token resets a known user's password) and unknown users NRE → 500. **FIXED in Wave 1 tranche 4** (`||` + status propagation in `RecoverPasswordCommandHandler`); Gap-Target tests in `PasswordResetFlowTests`.
- Tax report rolls up **GST child accounts via `ParentAccountId`** — the seed creates parents 1150/2150 with children 1150-01/2150-01 linked; without the hierarchy the report returns 0.
- Daily sale report semantics: GrossSales = pre-tax subtotal, `itemsSoldCount` = item ROW count, `AverageSale` = net-of-tax per transaction; window is `[date, date+1)` — send midnight UTC.
- **Opening-balance posts need the "5555" partner account**: `AddOpeningBalanceCommandHandler` calls `GetByAccountCodeAsync("5555")` then dereferences `openingBalanceAdjustment.Id` — without a seeded 5555 "Opening Balance Adjustment" ledger account the handler catches the NRE and returns 500 "error while saving Opning balance" (sic). The test seed now ships one (`TestIds.OpeningBalanceAdjustmentId`, Equity/Capital).
- **Daily purchase report needs BOTH ledger codes 2100 AND 4200**: `GetDailyPurchaseReportCommandHandler` dereferences `accountPayable.Id`/`discountReceived.Id` from `_ledgerAccountRepository.All.Where(2100||4200)` — without a seeded 4200 "Discount Received" account the NRE surfaces as an EF expression-tree evaluation failure → 500 "error while geting dailyPurchase report". The test seed ships both (`LedgerApId`, `LedgerDiscountReceivedId`, Income/Revenue). The NLog list endpoint needs `LOGS_VIEW_ERROR_LOGS` (distinct from the email `LOGS_VIEW_EMAIL_LOGS`).
- **N-41: country/city/variant create handlers 500 on SQLite FKs** — `AddCountry`/`AddCity`/`AddVariant` mapped new entities without stamping `CreatedBy`/`ModifiedBy` → insert with `Guid.Empty` → SQLite error 19 (FK). **FIXED** by injecting `UserInfoToken` and stamping both before `SaveAsync` (the pattern `AddEmailTemplateCommandHandler` uses); the Variant foreach also null-guarded (`?? []`). Pinned by Gap-Target `Should_AddCountry_ThenCity_When_Claimed` / variant create + duplicate 409 in `SettingsLookupTests`. Note: `AddVariantCommandValidator` demands ≥1 variant item (`422 "Alteast add one or more Variant item."` — send `variantItems`).
- **Route gotcha: many admin/console controllers declare `[Route("api")]` + FULL-path templates** — Country list = `GET /api/Countries` (NOT `/api/Country/Countries`, which matches `Country/{id}` and 400s "The value 'Countries' is not valid"); User list = `/api/User/GetUsers` (claimed) vs `/api/User/GetAllUsers` (unclaimed); Page list = `/api/Pages`. Always check the class-level `[Route]` before guessing URL paths.
- **Wave-2 CRUD template exemplar**: `CrudTemplate/BrandCrudTemplateTests.cs` — create/duplicate 409/update/soft-delete/list-excludes-deleted/get-404/permission 403/tenant isolation. Reuse this pattern per module (claims: check the controller's `[ClaimCheck]` first). **Roll-out done**: Units (`UnitConversationCrudTemplateTests` — note: no get-by-id route, soft-delete pinned via list), ProductCategories (`ProductCategoryCrudTemplateTests` — type is in `POS.Data.Entities`, not `POS.Data`), Suppliers (`SupplierCrudTemplateTests` — duplicate name returns **422** not 409, and create/update payloads must carry the non-nullable `BillingAddressId`/`ShippingAddressId` FKs, e.g. `TestIds.SupplierS1AddressId`), Customers (`CustomerCrudTemplateTests` — duplicate name 422; `Customers(TenantId, MobileNo)` is an **unguarded UNIQUE index** — duplicate mobile → generic 500, no 409/422 net; use unique mobiles in payloads), Locations (`LocationCrudTemplateTests` — duplicate name surfaces as **HTTP 400** with `statusCode:409` in the body because `AddLocation` hardcodes `BadRequest`; `Locations.FBRKey` is NOT NULL — always send `fbrKey`).

## Frontend test infrastructure facts (hard-won)
- The Angular 20 test target uses `@angular/build:karma` with `"karmaConfig": "karma.conf.js"`. `karma.conf.js` uses `browsers: ['ChromeHeadlessNoSandbox']` plus large disconnect/activity timeouts. Without the no-sandbox launcher the single big browser process intermittently FREEZES mid-suite (DISCONNECTED at random executed counts); with it the suite runs 241/241 in ~15s. Never use plain `ChromeHeadless`.
- `app.config.ts` providers are NOT replicated by TestBed. Every component spec needs `imports: [Component, TranslateModule.forRoot()]` and `providers: [provideHttpClient(), { provide: MatDialogRef, useValue: {} }, { provide: MAT_DIALOG_DATA, useValue: {} }, { provide: JwtHelperService, useValue: {} }, CurrencyPipe, provideNativeDateAdapter()]`. Omitting them surfaces as NG0201 for `_HttpClient` / `_TranslateService` / `JwtHelperService` (via `SecurityService -> WrLicenseService` field-inject) / `_CurrencyPipe` / DateAdapter / `MatMdcDialogData`.
- Components consuming `ActivatedRoute` need a route mock with BOTH `snapshot` (resolver data under `snapshot.data`) AND Observable-style `data`/`queryParams`/`paramMap`/`url` (emit via `of({...})` or `{ subscribe..., pipe: ... }`) because constructors call `route.data.subscribe(...)` / `route.data.pipe(...)`.
- Components with `input.required<T>()` / required `@Input()` fail with NG0950 on smoke-create: set the input via `setInput(...)` (or property assign) BEFORE `fixture.detectChanges()`.
- All components are STANDALONE - specs must use `imports: [ComponentClass]`, never `declarations:` (compiler rejects standalone-in-declarations).
- Never weaken assertions to make a spec pass. For count mismatches (e.g. CacheInterceptor "expected 1 to be 3") fix the FIXTURE data/seed so the real filter produces the asserted count. The only original assertion changed was the dead scaffold check `h1 "Hello, posnew"` in `app.spec.ts`, replaced with `<app-loading-indicator>` + `<router-outlet>` presence.
- Keep TestBed module config as a multi-line object; single-line `configureTestingModule({...});` breaks injected providers/imports.

- Service-spec pattern (established): `provideHttpClient()` + `provideHttpClientTesting()` + `HttpTestingController`; helper `expectUrl(method, url)` = `httpMock.expectOne(r => r.method === method && r.url === url)` (query params break exact-string matching); `httpMock.expectOne('url?baked=1')` for params baked into template literals; mock `CommonHttpErrorService` via SpyObj; error-propagation via `handleError.and.callFake(err => throwError(() => ({code: err.status})))`; `httpMock.verify()` in afterEach. Every `it` needs ≥1 expect (Karma warns "has no expectations" otherwise).
- Karma gotchas: `@microsoft/signalr` module exports are NOT writable — patch `signalR.HubConnectionBuilder.prototype.withUrl/withAutomaticReconnect/build` with spyOn+callFake instead; CDK `Overlay.scrollStrategies` is a property (`ScrollStrategyOptions`), not a method — assign a fake object rather than adding it to `createSpyObj` method list; `Object.keys(['a','b'])` returns array INDEXES — iterate the array directly; `Object.assign(...) as T` needed when building typed resource-parameter fixtures.
