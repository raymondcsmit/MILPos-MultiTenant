# Workflow Document 06 — Accounting & Finance Workflows

**Scope:** The double-entry engine, all strategy journal-entry mappings, payment processing, customer ledger, opening balances, financial years, year-end closing, payroll, and loans.

---

## WF-6.1 — The Central Transaction Pipeline

**Service:** `AccountingService.ProcessTransactionAsync` (POS.MediatR/Accouting/Services/AccountingService.cs:26-134). Every inventory-affecting event funnels here.

Exact sequence:
1. **Resolve open FinancialYear** (31): first `!IsClosed` FY; stamped on everything.
2. **Create Transaction header** (33-44): type, BranchId (=business location), narration, ReferenceNumber (=business order number); `TransactionNumber` generated by `TransactionRepository.GenerateTransactionNumberAsync` (POS.Repository/Accouting/Transaction/TransactionRepository.cs:69-97) — `{PREFIX}-{yyyyMMdd}-{seq:D4}`, e.g. `SAL-20260828-0007`. Prefixes: SAL, PUR, SAL-RET, PUR-RET, EXP, ADJ, PAY, PRL, LPA, LRE, OBL, YEC, DRE, STO.
3. **Build TransactionItems** (47-78): per line — DiscountAmount (fixed or % of qty×price, 64); TaxAmount = (line − discount) × tax% (66); LineTotal (67); attach TransactionItemTaxes from TaxIds (69-75).
4. **Header totals** (81-85): SubTotal = Σ gross; DiscountAmount = Σ line + FlatDiscount; TaxAmount = Σ line taxes; **TotalAmount = Math.Floor(SubTotal − Discount + Tax)**.
5. **Persist header** (87-91) — **⚠ the `<= -1` failure checks have empty bodies** (88-91, 106-109, 157-160, 187-190): persistence failures silently ignored.
6. **Strategy dispatch** (94-95) via `TransactionStrategyFactory` (Strategies/TransactionStrategyFactory.cs:16-30):

   | TransactionType | Strategy |
   |---|---|
   | Purchase | PurchaseStrategy |
   | PurchaseReturn | PurchaseReturnStrategy |
   | Sale | SaleStrategy |
   | SaleReturn | SaleReturnStrategy |
   | Expense | ExpenseStrategy |
   | StockAdjustment | StockAdjustmentStrategy |
   | StockTransferFromBranch | SaleStrategy (L26) |
   | StockTransferToBranch | PurchaseStrategy (L27) |
   | other | NotSupportedException |

7. **Inventory update** (98) — see WF-5.0.
8. **TaxEntries** (101) — `TaxService.ProcessTaxEntriesAsync` (Services/TaxService.cs:9-38): Input for Purchase/Expense/PurchaseReturn; Output for Sale/SaleReturn; one TaxEntry per item with tax.
9. **Status = Completed**, save (103-109).

**Entry construction:** `AccountingEntryFactory.CreateEntryAsync(...)` (Factories/AccountingEntryFactory.cs:9-35).

### Journal-entry model design decision
**One `AccountingEntry` row = one balanced entry** storing BOTH legs: `DebitLedgerAccountId` + `CreditLedgerAccountId` + `Amount` (POS.Data/Entities/Accounts/AccountingEntry.cs:14-18) — not one row per leg. `EntryType` classifies: Regular, Tax, Discount, RoundOff, Inventory, OpeningBalance, YearEndClosing, Salary, Loan (Accounts/Enums.cs:10-21).

## WF-6.3 — Strategy Journal-Entry Mappings (Complete Reference)

### Sale (SaleStrategy.cs:18-160) — see WF-3.2 table
Main Dr AR/Cr Sales; Output GST Dr AR/Cr GST-child; COGS Dr 5100/Cr 1200; Discount Dr 5200/Cr 4100; Round-off ±.

### Purchase (PurchaseStrategy.cs:18-132) — see WF-4.1 table
Main Dr Inventory/Cr AP; Input GST Dr GST-child/Cr AP; Discount Dr AP/Cr 4200; Round-off ±.

### Sale Return (SaleReturnStrategy.cs:18-164)
Exact mirror of Sale except round-off repeats the *sale* direction convention (147-149 — copy-paste, not mirrored):
Dr Sales/Cr AR; Dr GST-child/Cr AR; Dr Inventory/Cr COGS; Dr Sales/Cr Discount Given.

### Purchase Return (PurchaseReturnStrategy.cs:17-132)
Dr AP/Cr Inventory; Dr AP/Cr Input-GST-child; Dr 4200/Cr AP; Round-off ±.

### Expense (ExpenseStrategy.cs:19-88)
| Entry | Debit | Credit | Amount |
|---|---|---|---|
| Main (36-47) | General Expense 5300 | Cash 1050 (AP 2100 fallback only if no cash account, L31) | SubTotal |
| Input GST (49-87) | Input-GST child | Cash/AP | **⚠ computed on whole transaction total per tax (L59) and dictionary OVERWRITES per tax account (60-61)** — multiple taxes/items collapse |

Creation path: `AddExpenseCommandHandler` (POS.MediatR/Expense/Handlers/AddExpenseCommandHandler.cs:114-166) — builds a real Transaction header (`SubTotal = Amount − TotalTax`, L125) via `_expenseRepository.ProcessTransactionAsync`, then a **temp Transaction shell** with a fake item carrying `ExpenseTaxIds`, run through ExpenseStrategy (165). Update path (142-215): hard-deletes old transaction + entries, re-posts. Delete path flips type to SaleReturn for inventory reversal (DeleteExpenseCommandHanlder L90) — harmless (Expense ⇒ stock delta 0) but confusing.

### Stock Adjustment (StockAdjustmentStrategy.cs:18-106) — see WF-5.1
Gain: Dr Inventory/Cr 5400 (+GST entries Dr 1150/Cr AP); Loss: Dr 5400/Cr Inventory.

### Payroll (PayrollStrategy.cs:19-113) — accrual + settlement in one transaction
Phase 1 per component (EntryType.Salary, ref = payroll.Id): **Dr component expense / Cr Salary Payable 2200**:

| Component | Account |
|---|---|
| BasicSalary 6100, Bonus 6110, Commission 6120, FestivalBonus 6130, TravelAllowance 6140, MobileBill 6150, FoodBill 6160, Advance 6170, Others 6190 | (L41-104) |

Phase 2 settlement (106-111): **Dr Salary Payable 2200 / Cr Bank 1060 (PaymentMode.BANK) or Cash 1050** for totalPayroll. Net P&L: all staff costs expensed; 2200 passes through at zero.

Handler: `AddPayrollCommandHandler` (Accouting/Payroll/Add, 34-97): save Payroll + attachment; create TransactionType.Payroll transaction (prefix PRL, TotalAmount=TotalSalary); call strategy; accounting exceptions swallowed (81-84). Read/download handlers in Get/Download folders.

### Loans
**Take loan** — `AddLoanDetailCommand` (Accouting/LoanDetail/AddLoanDetailCommand.cs:41-148):
1. Ensure parent liability "To Loan Account" 7000 (43-60).
2. Auto-number per-loan "Loan Payable – {Lender}" (next 7xxx+10 from 7010, 62-88) + "Interest On Loan Account – {Lender}" expense (89-100).
3. Save **LoanDetail** linking both accounts (102-114).
4. TransactionType.LoanPayable transaction (prefix LPA, 123-136) → `LoanStrategy.ProcessLoanAsync` (Strategies/LoanStrategy.cs:21-31): **Dr Bank 1060 / Cr Loan Payable**, EntryType.Loan.

**Repay loan** — `AddPartialRePaymentOfLoanCommand` (37-84): create **LoanRepayment** (50-59); TransactionType.LoanRepayment (prefix LRE, TotalAmount = Principal + Interest, 61-74) → `ProcessPaymentOfLoanAsync` (32-51):
- Principal>0: Dr Loan Payable / Cr Bank (39-44).
- Interest>0: Dr Interest Expense / Cr Bank — **⚠ BUG at L48: amount passed is `loanDetail.LoanAmount`, not `loanRepayment.InterestAmount`** → the interest entry posts the full original loan amount instead of the interest due.

### Manual General Entry — `AddGeneralEntryCommandHandler` (Accouting/GeneralEntry/Add, 28-75)
Open FY; reference user-supplied or DRE-generated; TransactionType.DirectEntry (SubTotal=TotalAmount=Amount, Completed); ONE AccountingEntry with **user-chosen** debit + credit accounts, EntryType.Regular. Free-form journal — any account to any account. Validated by FluentValidation.

### Opening Balance — `AddOpeningBalanceCommandHandler` (Accouting/LedgerAccount/Add, 31-81)
TransactionType.OpeningBalance (OBL), EntryType.OpeningBalance:
- Debit-type: **Dr selected account / Cr 5555 Opening Balance Equity**.
- Credit-type: **Dr 5555 / Cr selected account**.
(`LedgerAccount.OpeningBalance` entity field is display metadata; transactional opening balances live in AccountingEntry rows.)

## WF-6.4 — Payment Processing Engine

**Service:** `PaymentService.ProcessPaymentAsync` (Accouting/Services/PaymentService.cs:28-122):
1. Resolve open FY (38); narration label per source type ("Sale Payment", "Sale Refund Payment", …) (42-50).
2. Create separate **TransactionType.Payment** transaction (52-65). **⚠ `Id = paymentDto.TransactionId` (54) defaults to Guid.Empty** — SO/PO payment handlers never set TransactionId (PaymentDto.cs:9).
3. Strategy via `PaymentStrategyFactory.GetStrategy` (Strategies/IPaymentStrategyFactory.cs:25-40) — **always FullPaymentStrategy**; partial branch commented out (dead code).
4. Validate (FullPaymentStrategy: Amount>0 only, 23-47); process; save.

**FullPaymentStrategy.CreatePaymentAccountingEntriesAsync** (FullPaymentStrategy.cs:70-164) — payment account by method (78-83): Cash→1050; DebitCard/CreditCard/UPI/NetBanking→1060; default (incl. Cheque)→1050:

| Source type | Debit | Credit |
|---|---|---|
| Sale (90-107) | Cash/Bank | AR 1100 |
| SaleReturn | AR 1100 | Cash/Bank (refund out) |
| Purchase (108-126) | AP 2100 | Cash/Bank |
| PurchaseReturn | Cash/Bank | AP 2100 (refund in) |
| StockAdjustment Gain (127-144) | AP | Cash/Bank |
| StockAdjustment Loss (145-161) | Cash/Bank | AP |

All EntryType.Regular. **⚠ `transaction.PaidAmount/BalanceAmount` never updated in this strategy** (only unreachable PartialPaymentStrategy 66-76 would) — accounting-side balance tracking is inert; SO/PO-level `TotalPaidAmount`/`PaymentStatus` are authoritative.

**Refunds:** `PaymentService.RefundPaymentAsync` (155-231) creates negative-amount PaymentEntry and adjusts Paid/Balance — but its accounting-entry call is commented out (199); `CreateRefundAccountingEntriesAsync` (233-299) exists callable. **Generic reversal engine:** `AccountingService.ReverseTransactionAsync` (209-270) clones every entry with legs swapped (REV- reference), reverses inventory, sets Status=Reversed — **no handler currently invokes it**; live reversals use the delete-and-repost or type-flip patterns instead.

## WF-6.5 — Customer Ledger Workflow (Sub-Ledger, FIFO Application)

**Entity:** CustomerLedger (POS.Data/Entities/CustomerLeadger/CustomerLedger.cs:10-29): Date, CustomerId, AccountName, LocationId, Description, Amount, Reference, running **Balance**, Overdue, Note. Not double-entry; GL-side exposure is AR 1100.

**Write path — `AddCustomerLedgerCommandHandler`** (POS.MediatR/CustomerLedger/Add, 31-118) — "customer pays money into their account":
1. Reject if `Amount > Overdue` (35-38).
2. Fetch open sales orders (PaymentStatus Pending/Partial), **FIFO by CreatedDate** (44-48).
3. Last ledger row's Balance (51-56); `totalAvailable = previousBalance + request.Amount` (59).
4. Loop orders: `payAmount = min(remaining, order.TotalAmount − order.TotalPaidAmount)`; dispatch **AddSalesOrderPaymentCommand** per order (73-82) — posts real GL payments (Dr Cash/Cr AR) + updates orders; accumulate applied (83-89).
5. Remainder becomes new credit **Balance** (93); notes record applications (96-100).

**Read paths:** overdue = Σ(TotalAmount − TotalPaidAmount) over open orders (GetSalesOrderOverdueByCustomerIdCommandHandler 16-32); ledger listing/search with filters (GetAllCustomerLedgerCommandHandler + CustomerLedgerRepository.GetAllCustomerLedger 19-55); single + delete handlers.

## WF-6.6 — Financial Year & Year-End Closing Workflow

**FY CRUD:** simple (Accouting/FinancialYear/*); years auto-created at tenant registration (calendar year, TenantRegistrationService.EnsureCurrentFinancialYearAsync 410-428). Every transaction/entry stamps the open FY id; FY-scoped reports filter on `AccountingEntry.FinancialYearId`.

**Year-end close — `AddYearEndClosingCommandHandler`** (Accouting/YearEndClosing/Add, 37-228):
1. Load the single open FY; stamp ClosedDate/ClosedBy (41-47).
2. Create next FY (+1 year, IsClosed=false) (49-56).
3. Load all FY entries with accounts (59-62), branch ids (63), ledger accounts (64); resolve 3200 Retained Earnings, 3100 Income Summary, 5555 Opening Balance Equity (65-67).
4. **Per branch** (69):
   - `incomeTotal` = Σ amounts **credited** to Income accounts; `expenseTotal` = Σ **debited** to Expense accounts (71-78) — **⚠ filtered by FY only, not by the loop's branch** (each branch DTO shows company-wide totals).
   - `netProfitOrLoss = income − expense` (82).
   - YEC transaction (TotalAmount = |net|, old FY) (93-106); OBL transaction for new FY (TotalAmount=0) (108-121).
   - **Closing entry** (EntryType.YearEndClosing, 123-139): profit → Dr 3100 / Cr 3200; loss → Dr 3200 / Cr 3100. (Income/expense accounts never zeroed — they simply stop carrying forward.)
   - **Opening-balance carry-forward** (140-211): recompute per-account Dr/Cr for that branch (140-147), append closing entry (150-158); for every account **excluding Income, Expense, IsTemporary** (185): closingBalance = Dr − Cr (188); if ≠0 write new-FY OBL entry — debit balances Dr account/Cr 5555; credit balances Dr 5555/Cr account (191-203).
5. Add new FY; old `IsClosed=true`; save (213-220).

## End-to-End Worked Example (credit sale → collection → reporting)

Sell 10 units @ 100 (line disc 10%, 5% GST, purchase price 60, flat discount 50, round-off +2):

1. **Order posted** (WF-3.2) → SaleStrategy entries:
   - Dr AR 900 / Cr Sales 900
   - Dr AR 47.50 / Cr Output-GST(VAT-5%) 47.50
   - Dr COGS 600 / Cr Inventory 600
   - Dr Discount Given 150 / Cr Sales 150
   - Dr AR 2 / Cr Round Off 2
   Stock −10; Output TaxEntry 47.50.
2. **POS cash payment** (WF-3.7) → PAY transaction → Dr Cash 949.50 / Cr AR 949.50 + PaymentEntry.
3. **Refund/correction**: delete payment → Dr AR / Cr Cash 949.50.
4. **Reports**: P&L revenue credits 4100 = 1050 (900+150), COGS 600; Balance Sheet AR +949.50 then settles; Cash Flow cash-in grouped under AR; GST report output-net 47.50.

## Known Quirks & Risks (facts from code)

1. Partial payment strategy dead code; PaidAmount/BalanceAmount unmaintained.
2. Payment transaction id reuse — Guid.Empty when TransactionId unset.
3. **Loan interest posts wrong amount** (LoanDetail.LoanAmount instead of InterestAmount).
4. Sale discount credits Sales (revenue overstated; AR gross) — offsets via Discount expense; AR ≠ TotalAmount.
5. Expense GST computed on whole total per tax + dictionary overwrite (multi-tax collapse).
6. Year-end income/expense totals not branch-filtered inside per-branch loop.
7. Round-off narrations swapped between Sale/SaleReturn (copy-paste).
8. Gain/loss detection by narration substring (2 places).
9. Transfers post AR/AP + revenue/COGS between own branches — no elimination.
10. ReverseTransactionAsync exists but uncalled; live reversals hard-delete or type-flip.
11. Trial Balance ignores opening balances and FY (date-range only) while Balance Sheet/CashBank/Tax are FY-scoped — reports can disagree same-day.
12. P&L report counts only account 5300 as expense — payroll 6xxx, discounts 5200, stock-loss 5400, round-off 5900 excluded from that report's expense line.
13. SaveAsync failure checks have empty bodies throughout the accounting services.
