## PHASE 2 — SYSTEMATIC API TESTING

Test every API endpoint thoroughly before testing the UI.

### A. Authentication & Authorization Endpoints

1. POST /api/auth/login (or equivalent):
   - Login with valid credentials → verify JWT token is returned.
   - Login with invalid credentials → verify 401 Unauthorized.
   - Login with empty fields → verify 400 Bad Request with validation messages.
   - Login with SQL injection payload → verify it is rejected.
   - Capture the JWT token for use in subsequent requests.
2. Token validation:
   - Call a protected endpoint without a token → verify 401.
   - Call a protected endpoint with an expired token → verify 401.
   - Call a protected endpoint with a malformed token → verify 401.
   - Call a protected endpoint with a valid token → verify 200.
3. Role-based access:
   - Call admin-only endpoints as a regular user → verify 403 Forbidden.
   - Call admin-only endpoints as an admin → verify 200.
4. Registration (if applicable):
   - Register with valid data → verify success.
   - Register with duplicate email/username → verify error.
   - Register with weak password → verify validation error.

### B. CRUD Endpoints — Every Entity

For EVERY entity/resource in the API (Products, Categories, Suppliers, Customers, Orders, Inventory, Users, etc.):

1. GET (List All):
   - Verify returns all records (with proper pagination if implemented).
   - Test query parameters: page, pageSize, sort, filter, search.
   - Test with no records in database.
   - Verify response structure matches expected DTO.

2. GET (Single by ID):
   - Verify returns correct record with all fields.
   - Test with non-existent ID → verify 404.
   - Test with invalid ID (string, negative number, zero).

3. POST (Create):
   - Create with all valid fields → verify 201 Created.
   - Verify the Location header is returned.
   - Create with missing required fields → verify 400 with validation messages.
   - Create with duplicate unique fields (e.g., duplicate SKU) → verify error.
   - Create with invalid data types.
   - Create with extremely long strings.
   - Create with special characters and HTML.
   - Verify the created record matches what was submitted.

4. PUT/PATCH (Update):
   - Update with valid data → verify 200 and changes persist.
   - Update non-existent record → verify 404.
   - Update with invalid data → verify 400.
   - Partial update (PATCH) → verify only specified fields change.
   - Update with same data → verify no error.

5. DELETE:
   - Delete existing record → verify 200/204.
   - Delete non-existent record → verify 404.
   - Delete record that has child/related records → verify cascade behavior (should it fail? should it cascade?).
   - Attempt to delete after already deleting → verify 404.

### C. POS-Specific API Testing

1. Sales/Transactions:
   - Create a sale with multiple items → verify total calculation is correct.
   - Create a sale with quantities exceeding stock → verify rejection or appropriate handling.
   - Verify tax calculations are correct.
   - Verify discount application works.
   - Verify stock is reduced after a sale.
   - Test voiding/canceling a transaction.
   - Test partial returns/refunds if supported.
   - Test with zero-quantity items.
   - Test with negative prices or quantities.

2. Inventory/Stock Management:
   - Add stock (receive inventory) → verify stock quantity increases.
   - Remove stock (manual adjustment) → verify stock quantity decreases.
   - Transfer stock between locations (if supported).
   - Test stock level alerts/notifications (if implemented).
   - Test minimum stock threshold warnings.
   - Verify stock counts are accurate after multiple transactions.
   - Test concurrent stock updates (race condition awareness).

3. Reporting Endpoints (if any):
   - Sales report for a date range → verify data accuracy.
   - Inventory report → verify stock levels match expected.
   - Daily/weekly/monthly summaries → verify calculations.
   - Test with date ranges that have no data.
   - Test with future dates.
   - Test with extremely large date ranges.

4. Search & Filtering:
   - Search products by name, SKU, barcode, category.
   - Filter by multiple criteria simultaneously.
   - Search with no results.
   - Search with partial matches.

### D. Data Integrity Testing

1. Verify foreign key relationships are enforced (cannot create order with non-existent product).
2. Verify unique constraints are enforced.
3. Verify decimal precision for prices and quantities (no floating point errors).
4. Verify date fields store and return correct values (timezone handling).
5. Verify soft delete behavior if implemented (records are marked deleted, not removed).
